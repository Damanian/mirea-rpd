# MIREA RPD (MCP-коннектор к rpd.mirea.ru)

Отдельный MCP-сервер и Python-библиотека для работы с сервисом рабочих программ дисциплин РТУ МИРЭА ([rpd.mirea.ru](https://rpd.mirea.ru)).

## Возможности

* 🔍 **Поиск и навигация:**
  * Поиск дисциплин по ключевым словам и учебным планам (РУП).
  * Получение списка кафедр, направлений подготовки и профилей.
  * Фильтрация по учебным годам (`2026-2027` и др.).
* 📖 **Чтение и анализ рабочих программ:**
  * **Титульный лист:** кафедра, составители, рецензенты, компетенции (УК, ОПК, ПК), индикаторы.
  * **Содержание дисциплины:** разделы, темы, часы лекций, практических занятий, лабораторных работ, СРС.
  * **Фонд оценочных средств (ФОС):** формы контроля, критерии оценивания, типовые контрольные задания, вопросы к зачёту/экзамену.
  * **Литература:** списки основной и дополнительной литературы, ссылки на ЭБС.
  * **Полный паспорт РПД:** сборка всех блоков программы в единую структуру.
* 💾 **Выгрузка документов:** скачивание черновиков РПД и сопутствующих файлов на диск.
* **Автозаполнение через ИИ:** типизированный шаблон для результатов обучения, разделов и занятий, ФОС, литературы, ПО, справочных систем, аудиторий, целей и титульных данных. Проверка часов по каждому семестру, сохранение и повторное чтение результата.
* 🤖 **MCP-сервер:** поддержка протокола Model Context Protocol (stdio) для подключения к Claude Desktop, Cursor, Antigravity и другим AI-клиентам.

## Установка и запуск

```bash
# 1. Перейдите в папку проекта
cd "C:\Users\Damanian\Documents\ChatGPT\MIREA RPD"

# 2. Создайте виртуальное окружение и установите зависимости
```

## Доступные MCP-инструменты

* `rpd_status()` — проверить активность сессии в `rpd.mirea.ru`.
* `rpd_departments(acc_year)` — список кафедр для учебного года.
* `rpd_plan_entities(acc_year, dep_id)` — названия дисциплин кафедры и их `objectType`.
* `rpd_search_disciplines(query, acc_year, dep_id)` — поиск дисциплин в учебных планах.
* `rpd_get_work_programs(acc_year, disc_name, rup_row_id, rup_name)` — список РПД для найденной строки плана; используйте данные из поиска.
* `rpd_get_title(rup_row_id, rp_id)` — титульный лист (составители, компетенции, часы).
* `rpd_get_content(rup_row_id, rp_id)` — разделы, темы занятий, часы лекций/практик/лаб.
* `rpd_get_fos(rup_row_id, rp_id)` — фонд оценочных средств, вопросы к экзамену/зачету.
* `rpd_get_literature(rup_row_id, rp_id)` — рекомендованная литература и ЭБС.
* `rpd_get_full_program(rup_row_id, rp_id)` — сводный паспорт программы.
* `rpd_download_draft(rup_row_id, rp_id, save_path)` — резервная копия черновика в собственном XML-формате `.rpdx`.
* `rpd_get_autofill_context(rup_row_id, rp_id?)` — программа, настройки сайта, права, бюджеты часов и JSON Schema шаблона.
* `rpd_search_resources(rup_row_id, kind, query, rp_id?)` — поиск реальных записей каталогов литературы, ПО, справочных систем и аудиторий.
* `rpd_validate_template(template, hour_budget?, semester_budgets?, allowed_indicators?)` — локальная проверка без записи.
* `rpd_autofill_program(rup_row_id, template, rp_id?, dry_run?, content_mode?)` — полное заполнение с проверкой соответствия учебному плану.
* `rpd_apply_template(rup_row_id, rp_id, template, dry_run?, content_mode?)` — частичное обновление с проверкой сохранения.
* `rpd_export_template(rup_row_id, rp_id, save_file?, include_fos_files?)` — экспорт содержания, результатов обучения, справочников и файлов ФОС в повторно применимый JSON.

## Автозаполнение по запросу ИИ

Текст готовит ИИ в подключённом MCP-клиенте. Отдельный ключ модели коннектору не нужен: он предоставляет учебный план, схему ввода и инструменты записи.

1. Спросите дату утверждения и номер протокола. Передайте их в `title.protocol_date` и `title.protocol_number`; дата принимается как `ДД.ММ.ГГГГ` или `YYYY-MM-DD`. Если пользователь явно просит пока не заполнять эти поля, используйте `defer_approval=true`. Без данных или явного решения отложить полное автозаполнение вернёт `requires_user_input=true` до обращения к сайту.
2. Найдите дисциплину через `rpd_search_disciplines`, выберите нужную строку `rupRowId` и прочитайте `rpd_get_autofill_context`.
3. Составьте шаблон по учебному плану и содержательным референсам. Семестры, часы и индикаторы берите из контекста, ID ресурсов — из `rpd_search_resources`. Для каждого занятия распишите конкретные вопросы, методы и ожидаемый результат. Пределы одного занятия: лекция — 2 ч., лабораторная — 4 ч., практика — 2 ч., СРС — 4 ч. Для большого объёма нужны отдельные содержательные занятия; суммы по семестрам сохраняются.
4. В `learning_outcomes` заполните все индикаторы и категории: `1` — знать, `2` — уметь, `3` — владеть. Для каждой категории каждого индикатора задайте `current_tasks` (минимум 5) и `intermediate_tasks` (минимум 10). У каждого задания — тип, условие, время и полный ключ/эталон ответа. Коннектор создаст DOCX по приложенному табличному шаблону и прикрепит к нужным результатам. Готовые DOCX через `current_fos`/`intermediate_fos` также проходят проверку структуры и количества заданий.
5. Проверьте шаблон через `rpd_validate_template` с бюджетами из контекста, затем вызовите `rpd_autofill_program`.
6. Проверьте `success`, `saved_to_db`, `verified`, `approval_deferred`, `errors` и ссылку в результате. При ошибке до сохранения изменения могут остаться в серверном черновике; сохранение в базу не выполняется.

Без `rp_id` создаётся отдельная РПД рядом с существующей. Передавайте `rp_id`, возвращённый первым успешным вызовом, для повторного запуска. Повторное применение того же шаблона к этой РПД не создаёт дубликаты.

`dry_run=true` проверяет только структуру локального шаблона: он не подключается к сайту, не проверяет права и справочники. Реальная проверка учебного плана выполняется перед записью. Даже чтение контекста через API сайта может открыть серверный черновик и занять место в лимите.

`content_mode="merge"` добавляет и обновляет занятия. `"replace"` также удаляет обычные разделы и прежние обычные занятия, которых нет в шаблоне, в том числе внутри оставленных разделов. Аттестация сохраняется. Ссылки на ресурсы объединяются с существующими. Лишние часы выявляются при итоговой сверке и блокируют сохранение. Полное заполнение также проверяет часы контроля и контактной аттестации по плану.

Титульные данные, составители, рецензенты и протоколы передаются только по фактическим сведениям. `comments_text` — замечания проверяющего, для него требуется отдельное право `canWriteComments`. Текстовые поля зависят от конфигурации сайта: при списочном режиме используйте справочники. Перед утверждением необходима содержательная проверка преподавателем.

Пример полного шаблона: [examples/schematics-autofill.json](examples/schematics-autofill.json), проверенные часы: [examples/schematics-hours.json](examples/schematics-hours.json). ID справочников в примере относятся к проверенному серверу и не подходят автоматически для другой дисциплины.

Пример обновлён по ответу пользователя «пока не заполняй» и содержит `defer_approval=true`; при новом запросе нельзя автоматически копировать это решение. Он включает 60 занятий и 90 заданий ФОС в 12 документах. Содержательный исходник примера: [examples/build_schematics.py](examples/build_schematics.py).

## Формат ФОС и правила заданий

Файлы создаются на основе обезличенной копии пользовательского шаблона в `assets/fos-template.docx`: сохраняются геометрия страницы, шрифты, стили и шесть колонок. Каждая строка содержит номер, правильный ответ, инструкцию с условием, код родительской компетенции, время в минутах и название дисциплины. Шапка повторяется на страницах, задание переносится целиком, последняя строка закрывает рамку таблицы.

Правила презентации от 25.06.2026:

- «Знать»: `matching` — соответствие, `sequencing` — последовательность. Ключ задаётся номерами от 1 в `correct`; для соответствия нужны `left_items`/`right_items`, для последовательности — `sequence_items`.
- «Уметь» и «владеть»: `open_response` — развёрнутый обоснованный ответ, `calculation` — решение задачи; полный эталон задаётся в `answer`.
- Для этих двух категорий также поддержаны `single_choice_justified` и `multiple_choice_justified`: варианты в `options`, номера в `correct`, обязательное обоснование в `explanation`. Обычный выбор ответа без обоснования не поддерживается.
- Для каждой категории каждого индикатора — минимум 5 текущих и 10 промежуточных заданий. Повторяющиеся задания, некорректные ключи, отсутствие ответа или времени блокируют ввод.

Старые поля `*_control_task1/2` не позволяют передать ключи и требуемое количество заданий. Они отклоняются с указанием перехода на структурированные наборы. Экспорт готовой РПД сохраняет ФОС как вложенные DOCX; данные утверждения автоматически не копируются в новый шаблон.

Локальная проверка примера:

```powershell
.venv\Scripts\mirea-rpd validate examples\schematics-autofill.json --budget-file examples\schematics-hours.json
```

Сессия по умолчанию хранится в `~/.mirea/rpd_session.json`. Для отдельного файла задайте переменную `MIREA_RPD_SESSION_FILE` при входе и запуске MCP. Файл содержит cookie доступа; не включайте его в Git.

## Проверка разработки

```powershell
.venv\Scripts\python -m pytest -q
.venv\Scripts\python -m ruff check src tests
```

Тесты проверяют ошибки API внутри HTTP 200, последовательные hash, реальные формы запросов и multipart ФОС, отказ от сохранения при расхождении, повторное применение и экспорт. Проверка MCP запускает отдельный процесс по stdio. Обычный pytest не обращается к реальному сайту.

Результаты проверки на реальном сайте описаны в [docs/autofill-testing.md](docs/autofill-testing.md).
