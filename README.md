# РПД МИРЭА — MCP-коннектор

Коннектор позволяет ИИ работать с [rpd.mirea.ru](https://rpd.mirea.ru): находить дисциплины, читать и заполнять рабочие программы, формировать ФОС по шаблону и сохранять результат.

Ниже — пошаговый сценарий от установки до готовой РПД. Команды приведены для **Windows PowerShell**. Нужны Git, Python 3.11 или новее, учётная запись с доступом к РПД и ИИ-клиент с поддержкой локальных MCP-серверов по stdio.

## Шаг 1. Скачайте и установите проект

Откройте PowerShell в папке, где хотите разместить проект:

```powershell
git clone https://github.com/Damanian/mirea-rpd-mcp.git
cd mirea-rpd-mcp
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
```

Все дальнейшие команды выполняйте из папки проекта. Активация окружения не требуется: команды обращаются к его Python напрямую.

## Шаг 2. Войдите в РПД

```powershell
.\.venv\Scripts\python.exe -X utf8 -m mirea_rpd login
```

Откроется локальная страница входа. Введите на ней логин и пароль от сервиса РПД. После успешного входа терминал сообщит, что сессия сохранена.

Если браузер не открылся, перейдите по адресу из терминала. Можно также ввести данные в терминале:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m mirea_rpd login --terminal
```

Проверьте вход:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m mirea_rpd status
```

Ожидаемый результат: **«Сессия активна и подтверждена сервером»**.

Сессия хранится в `~/.mirea/rpd_session.json`. Файл содержит cookie доступа: не публикуйте его и не отправляйте в чат. При блокировке входа дождитесь окончания срока, указанного сайтом, и повторите вход.

## Шаг 3. Подключите MCP к ИИ-клиенту

Узнайте абсолютный путь к Python установленного коннектора:

```powershell
(Resolve-Path .\.venv\Scripts\python.exe).Path
```

Добавьте локальный MCP-сервер в настройки своего ИИ-клиента. Для клиента с JSON-конфигурацией `mcpServers`:

```json
{
  "mcpServers": {
    "mirea-rpd": {
      "command": "C:\\Projects\\mirea-rpd-mcp\\.venv\\Scripts\\python.exe",
      "args": ["-X", "utf8", "-m", "mirea_rpd", "mcp"]
    }
  }
}
```

**Замените `command` на путь, полученный вашей командой.** В JSON обратные слеши записываются как `\\`. Если клиент предлагает отдельные поля, укажите путь к Python в поле команды, а `-X`, `utf8`, `-m`, `mirea_rpd`, `mcp` — отдельными аргументами.

Перезапустите подключение MCP или ИИ-клиент. Должны появиться инструменты с префиксом `rpd_`. Сервер запускается клиентом автоматически; отдельно держать команду `mcp` в терминале не нужно.

Команда входа и MCP должны запускаться под одним пользователем ОС, чтобы видеть одну сессию.

## Шаг 4. Найдите дисциплину

Напишите ИИ:

> Проверь подключение к РПД через rpd_status. Найди дисциплину «Схемотехника электронных устройств» за 2026–2027 учебный год. Покажи найденные учебные планы и существующие РПД. Пока ничего не заполняй.

Выберите нужный учебный план из результатов. Если ссылка уже есть, передайте её напрямую:

> Прочитай контекст РПД по ссылке https://rpd.mirea.ru/Rp?rupRowId=2019486. Покажи дисциплину, семестры, часы по видам занятий и индикаторы компетенций.

Для своей дисциплины используйте её ссылку. `rupRowId` определяет строку учебного плана, а `rpId` — конкретную рабочую программу.

## Шаг 5. Передайте материалы и запустите заполнение

Прикрепите к чату материалы дисциплины: существующую РПД, описание тем, методические указания, литературу или другие содержательные референсы. Вложения читает ИИ-клиент; MCP получает подготовленные им данные.

Пример запроса:

> Создай новую РПД рядом с существующей по ссылке https://rpd.mirea.ru/Rp?rupRowId=2019486.
>
> Используй приложенные материалы. Сначала прочитай контекст учебного плана и уточни дату утверждения и номер протокола. Подробно распиши темы и содержание каждого занятия. Сохрани часы по семестрам. Одно занятие: лекция — максимум 2 часа, лабораторная — 4, практика — 2, СРС — 4.
>
> Заполни результаты обучения по всем индикаторам: знать, уметь и владеть. Для каждой категории каждого индикатора подготовь минимум 5 текущих и 10 промежуточных заданий ФОС с ответами и временем выполнения. Используй табличный шаблон коннектора. Подбери литературу, ПО, справочные системы и аудитории из каталогов сайта.
>
> Проверь шаблон, заполни новую РПД, сохрани в базу и проверь результат повторным чтением. Верни ссылку и сообщи, что осталось незаполненным.

ИИ должен уточнить **дату утверждения и номер протокола**. Дату можно указать как `ДД.ММ.ГГГГ` или `YYYY-MM-DD`. Если данных пока нет, ответьте явно:

> Дату утверждения и номер протокола пока не заполняй.

Тогда ИИ передаст `defer_approval=true`. Это решение относится к текущему запросу. Составителей, рецензентов и другие титульные сведения также передавайте по фактическим данным.

Текст готовит модель подключённого ИИ-клиента. Отдельный ключ модели коннектору не нужен.

## Шаг 6. Проверьте результат

У успешного сохранения в отчёте должны быть:

```json
{
  "success": true,
  "saved_to_db": true,
  "verified": true,
  "errors": []
}
```

При отложенном утверждении дополнительно возвращается `approval_deferred=true`.

Откройте полученную ссылку и проверьте содержание занятий, часы, результаты обучения, документы ФОС, литературу и титульные данные. Автоматическая проверка подтверждает структуру, часы и сохранение; содержательную проверку выполняет преподаватель.

Без `rp_id` полное заполнение создаёт отдельную РПД. Для исправлений ИИ должен использовать ID уже созданной программы. Например:

> Исправь созданную РПД по этой ссылке: [вставьте ссылку с rupRowId и rpId]. Подробнее распиши содержание лабораторных. Сохрани часы учебного плана и проверь результат после сохранения.

При ошибке попросите показать `errors` и исправить эту же программу. Изменения до сохранения могут остаться в серверном черновике. Даже чтение контекста через API сайта может открыть черновик и занять место в лимите.

## Шаг 7. Сохраните резервную копию

Напишите ИИ:

> Скачай резервную копию черновика этой РПД в формате .rpdx. Также экспортируй JSON-шаблон с вложенными файлами ФОС для повторного использования.

`.rpdx` — собственный XML-формат сайта. JSON-экспорт содержит содержание, результаты обучения, ресурсы и DOCX ФОС. Данные утверждения автоматически в новый шаблон не копируются.

## Как оформляется ФОС

В комплект входит обезличенный [DOCX-шаблон](src/mirea_rpd/assets/fos-template.docx). Документы сохраняют его геометрию страницы, шрифты, стили и шесть колонок: номер, правильный ответ, инструкция с условием, код компетенции, время в минутах и название дисциплины.

| Категория | Допустимые задания |
| --- | --- |
| Знать | Соответствие, последовательность |
| Уметь, владеть | Развёрнутый ответ, расчёт, одиночный или множественный выбор с обязательным обоснованием |

Для каждой категории каждого индикатора нужны минимум **5 текущих и 10 промежуточных заданий**. У каждого задания должны быть условие, время и полный ключ или эталон ответа. Повторы и некорректные ключи блокируют ввод.

## Если что-то не работает

| Ситуация | Что сделать |
| --- | --- |
| Сессия не найдена или истекла | Повторить шаг 2 и проверить `status` |
| Вход работает в терминале, MCP просит войти | Проверить пользователя ОС и путь сессии у обоих процессов |
| MCP не запускается | Проверить абсолютный путь к Python, аргументы и JSON; перезапустить подключение |
| Сайт сообщает о лимите черновиков | Сохранить резервные копии и освободить ненужные черновики на сайте |
| Не сходятся часы | Получить актуальный контекст и исправить распределение по каждому семестру |

Для отдельного файла сессии можно задать `MIREA_RPD_SESSION_FILE`: один и тот же абсолютный путь при входе и в окружении MCP-сервера. По умолчанию переменная не требуется.

## Примеры и разработка

- [Полный JSON-пример](examples/schematics-autofill.json): 60 занятий и 90 заданий ФОС в 12 документах.
- [Бюджеты часов примера](examples/schematics-hours.json).
- [Справочник инструментов и формата автозаполнения](docs/autofill-reference.md).
- [Результаты проверки на реальном сайте](docs/autofill-testing.md).

Пример содержит `defer_approval=true` по явному решению пользователя. ID ресурсов и часы относятся к конкретной дисциплине: для другой программы нужно заново получить контекст и найти записи каталогов.

Локальная проверка примера без подключения к сайту:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m mirea_rpd validate examples\schematics-autofill.json --budget-file examples\schematics-hours.json
```

Установка зависимостей разработки и проверки:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check src tests examples
```

Обычный pytest не обращается к реальному сайту. Проверка MCP запускает отдельный процесс по stdio.
