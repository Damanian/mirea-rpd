## Исправленные особенности API

Ответ HTTP 200 может содержать `result=false`. Перед редактированием необходим `/Rp/Initialize`; запросы выполняются последовательно с актуальным hash и формами jQuery. После сохранения временные ID становятся постоянными. Перенос раздела использует индексы массива от нуля. ID записи МТО отличается от ID каталога. Сервер нормализует переводы строк в CRLF.

Несколько практик или СРС могут иметь одинаковый ID вида деятельности внутри одного раздела. После смены временных ID проверка сопоставляет их также по содержанию комментария. Иначе второе занятие ошибочно сравнивалось с первым; исправление закреплено отдельным тестом. В режиме replace прежние обычные занятия удаляются и внутри сохраняемых разделов, что позволяет содержательно дробить темы без удвоения часов.

В этой конфигурации оценки и задания контроля в текстовых полях Rp3 игнорируются. Они сохраняются в файлах ФОС, которые коннектор создаёт из шаблона или принимает в готовом виде. Заполнение скрытых полей без проверки не считается успехом.

## Границы проверки

Использован тестовый учебный материал; содержание требует экспертизы преподавателя. Утверждение, подписи, протоколы и публикация не выполнялись. Лимит черновиков остаётся ограничением сайта; коннектор сообщает его как ошибку и не удаляет чужие черновики автоматически.

ФОС создаются из обезличенной копии приложенного DOCX, а правила взяты из просмотренных 10 слайдов «ФОС лето 2026» от 25.06.2026. Сохранены геометрия страницы, таблица из шести колонок, стили и шрифты. Шапка повторяется, задания переносятся целиком, восстановлена нижняя граница таблицы. Неизменяемые части DOCX сравниваются побайтово; исходный пользовательский файл не изменён.

Вёрстка всех 32 страниц двенадцати итоговых ФОС проверена после экспорта через установленный Microsoft Word в скрытом режиме и растеризации пакетным Poppler. Обрезанного или наложенного текста не обнаружено. Программная проверка структуры и визуальная проверка не заменяют содержательную экспертизу преподавателя.

Сайт продолжает возвращать `hasChanges=true` даже после успешного сохранения. Поэтому признак возвращается как `draft_has_unsaved_changes` без подмены; сохранение дополнительно подтверждено отдельной проверкой из базы после удаления тестового черновика.

Резервные копии удалённых с разрешения пользователя черновиков и технические протоколы находятся локально в `.audit-cache`, исключены из Git. Cookie сессии в исходный код и отчёты не включались.
